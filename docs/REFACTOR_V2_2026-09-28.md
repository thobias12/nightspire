# Architecture refactor V2 — 2026-09-28

This is the second behavior-preserving architecture pass. V1 established domain folders; V2 reduces the remaining cross-cutting responsibilities and adds guardrails for parallel ChatGPT work.

## Goals

- make normal changes require reading fewer files;
- make ownership obvious to a new chat;
- prevent runtime import cycles before they reach GitHub Pages;
- separate debug/test plumbing from production coordination;
- keep persistence compatibility logic separate from integrity validation;
- keep low-level persisted schemas below world generation;
- avoid touching the active HUD redesign in PR #55.

## Changes in this pass

### App / QA

`app/Game.ts` no longer contains the large QA/debug mutation block. Dev controls, state staging and integrity-audit actions live in `qa/QaActions.ts`.

This removes production-coordinator dependencies on combat damage, forced immigration, stockpile QA filling, test-town staging and save validation. Game remains responsible for browser interaction and placement orchestration.

### Persistence

`persistence/SaveMigrations.ts` owns backward-compatibility mutations. `SaveLoad.ts` owns strict validation, serialization and deserialization orchestration.

A duplicated resource-node validation pass was removed. Save format/version behavior is unchanged.

### World schema

Map size, landscape and persisted `MapDefinition` now live in `data/map.ts`. The state model no longer imports its persisted map type from `world/MapGenerator.ts`.

### Rendering

Reusable Three.js geometry/texture constructors moved to `render/RenderPrimitives.ts`. `SceneRenderer.ts` remains a tracked legacy hotspot, but new reusable primitives have an explicit home.

### Architecture enforcement

`scripts/check-architecture.mjs` now parses TypeScript rather than relying only on import regexes. CI checks:

- runtime import cycles;
- forbidden upward dependencies;
- barrel `index.ts` files;
- resurrection of the generic `simulation/` folder;
- new TypeScript modules over 80 KiB.

The existing oversized HUD and SceneRenderer are allowlisted warnings, not examples to copy.

### Multi-chat workflow

`AGENTS.md` and `docs/AI_NAVIGATION.md` now require checking open PR filenames before touching hotspots and give short “change recipes” for common work.

## Bugs / drift found during audit

- Main and active HUD PR #55 both still contain planned-catalog entries for **Mine** and **Pleasure House** even though the real buildings are implemented and separately present in the catalog. Do not patch PR #55 from this branch; remove those stale planned entries during HUD integration.
- `gh-pages` is still an independently evolved source branch rather than generated deployment output. This is the largest remaining repository-maintenance risk because feature work often has to be transplanted twice.
- The broad simulation regression suite is still one large file with shared fixtures. Split it only after extracting domain fixtures; mechanically duplicating the 100+ line preamble would make maintenance worse.

## Remaining safe decomposition order

1. Finish/integrate the active HUD PR, then split HUD markup/projections/panels without changing the design again.
2. Extract Game planning/input state into a cohesive controller.
3. Split SceneRenderer by visual family using shared render context/primitives, not duplicated `instance()` helpers.
4. Extract shared test fixtures, then split `tests/simulation.test.mjs` by world/economy/population/combat/persistence.
5. Converge live-only source back into `main`, then make Pages a generated deployment branch so gameplay source has one authority.

## Verification contract

Every architecture change must pass:

```sh
npm run verify
```

For a Pages deployment, additionally verify the exact deployed head and live startup. The raw-TypeScript Pages loader is especially sensitive to runtime import cycles.
