# Architecture refactor V4 — HUD and renderer decomposition

V4 removes the final TypeScript size exceptions introduced during the earlier architecture cleanup.

## HUD ownership

The medieval HUD keeps the same runtime behavior and visual design, but its responsibilities are now navigable without opening one giant file:

- `ui/Hud.ts` — live update orchestration, DOM event wiring and panel state.
- `ui/HudTemplate.ts` — static DOM shell.
- `ui/HudContent.ts` — descriptions, labels and reusable UI fragments.
- `ui/HudCatalog.ts` — construction-card/catalog projection.
- `ui/HudTypes.ts` — public metrics/UI state contracts.
- `ui/MedievalHud.css` — presentation only.

`Hud.ts` is now below the 80 KiB architecture budget.

## Renderer ownership

`render/SceneRenderer.ts` now owns scene/camera/light orchestration, shared instancing and the world sync loop. Specialized rendering moved to:

- `render/PlacementGhostRenderer.ts` — transient placement previews.
- `render/PlanningOverlayRenderer.ts` — persistent blueprint/plot overlays.
- `render/FieldRenderer.ts` — field mesh lifetime, crop/soil decoration and field selection.
- `render/TownBuildingRenderer.ts` — procedural non-residential town/building visuals, props, nightlife and fortifications.
- `render/ResidentialRenderer.ts` — residential plots, boundaries, street thresholds and backyard compounds.
- `render/RenderPrimitives.ts` — reusable geometry/texture constructors from V2.

`SceneRenderer.ts` fell from roughly 157 KiB / 3,272 lines to roughly 43 KiB / 872 lines while keeping the public renderer API stable.

## Guardrail change

The architecture checker no longer allowlists `Hud.ts` or `SceneRenderer.ts`. Every TypeScript module now has the same 80 KiB navigation budget and runtime-cycle checks.

## Rules for future chats

- Add general building visuals to `TownBuildingRenderer.ts`, not `SceneRenderer.ts`.
- Add residential lot/compound visuals to `ResidentialRenderer.ts`.
- Add placement-preview visuals to `PlacementGhostRenderer.ts`.
- Add field-specific visuals to `FieldRenderer.ts`.
- Add static HUD markup to `HudTemplate.ts`; do not rebuild large static HTML inside `Hud.update()`.
- Put construction-card metadata/projection in `HudContent.ts` / `HudCatalog.ts`.
- Keep gameplay calculations out of UI/render modules.
