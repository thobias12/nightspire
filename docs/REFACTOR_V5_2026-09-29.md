# Architecture refactor V5 — HUD event ownership and navigation drift

V5 is a behavior-preserving maintainability pass on top of Architecture V4.

## HUD event ownership

The DOM/window event delegation that previously lived in the `Hud` constructor now lives in:

- `ui/HudEvents.ts` — click/change/focus/pointer delegation, import-file handling and transient drag gesture state.
- `ui/Hud.ts` — HUD state, panel positioning, live projections and update orchestration.

The extraction keeps the same action strings, selectors, event types and AbortSignal lifetime. It does not change the medieval HUD markup or CSS.

This gives `Hud.ts` meaningful headroom below the 80 KiB architecture ceiling so routine UI additions do not immediately hit the navigation budget.

## Architecture checker cleanup

V4 removed the last oversized-file allowlist. V5 removes the leftover unreachable warning/legacy-exception plumbing from `scripts/check-architecture.mjs`.

The rule is now represented exactly once: every TypeScript module above 80,000 bytes is a violation. Runtime import-cycle detection and dependency-direction checks are unchanged.

## Documentation corrections

- `docs/AI_NAVIGATION.md` no longer describes `Hud.ts` or `SceneRenderer.ts` as oversized.
- HUD event ownership is documented explicitly.
- The V4 renderer ledger now correctly assigns residential compounds to `ResidentialRenderer.ts`.
- `docs/ARCHITECTURE.md` states the uniform 80 KiB/no-cycle guardrail.

## Guardrails

No simulation, gameplay, persistence, renderer output, HUD markup, HUD CSS or action protocol changes are intended in V5.
